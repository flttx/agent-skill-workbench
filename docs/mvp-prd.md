# 个人 AI 工作操作系统 MVP 需求文档

> 状态：Draft  
> 版本：0.1  
> 日期：2026-08-06  
> 目标项目：`agent-skill-workbench`

## 1. 产品概述

### 1.1 产品定位

一个长期打开的个人工作驾驶舱，聚合多个项目的今日行动，并把想法、资料和外部任务转成可交给 Codex、Claude、Cursor 或 IDE 执行的任务。

### 1.2 目标用户

同时推进多个开发、设计或研究项目，日常使用浏览器、文件系统、IDE 和多个 AI Agent 的个人创作者/开发者。

### 1.3 核心问题

- 信息分散在网页、文件夹、IDE、GitHub 和不同 Agent 对话里。
- 有价值的想法没有稳定地转成任务。
- Agent 执行前缺少完整上下文，执行后结果容易丢失。
- 用户需要一个持续可见的全局行动列表，而不是更多资料归档页面。

### 1.4 MVP 目标

验证下面的闭环是否足够有用：

```text
捕获一个想法
→ AI 生成任务草稿
→ 关联项目
→ 推荐 Agent 与 Skill
→ 用户确认上下文
→ 打开指定 Agent 并注入任务
→ 保存执行过程和结果
```

### 1.5 成功标准

一个用户可以在 3 分钟内完成：

1. 输入一条模糊想法。
2. 得到可编辑的任务草稿。
3. 看到关联项目、来源、执行步骤、推荐 Agent 和推荐 Skill。
4. 选择 Agent 并打开对应应用，任务上下文已填入。
5. 回到工作台后保存执行结果、产物和下一步。

## 2. 产品模型

### 2.1 核心对象

| 对象 | 定义 | MVP 要求 |
|---|---|---|
| Task | 可执行、可追踪的工作单元 | 必须支持 |
| Project | 提供背景的项目容器 | 必须支持 |
| Source | 想法、网页、对话、文件或 GitHub 事项的来源 | 支持 URL、文本、文件路径 |
| Context Pack | 启动 Agent 前汇总的任务上下文 | 必须支持预览和编辑 |
| Agent | 执行任务的外部工具 | Codex、Claude、Cursor |
| Skill | 可复用的执行方法 | 先推荐和关联，Skill 草稿可审核 |
| Agent Run | 一次 Agent 执行及其结果 | 必须支持 |
| Daily Focus | AI 推荐的今日行动列表 | 必须支持用户确认 |

### 2.2 数据归属原则

外部任务系统、GitHub、文件系统和 Agent 应用可以继续作为事实来源。工作台保存任务镜像、外部引用、上下文、推荐、执行记录和结果，不默认复制所有外部数据。

## 3. 用户流程

### 3.1 想法转任务

1. 用户在首页快速输入想法。
2. 系统生成任务标题、目标、项目候选和执行步骤。
3. 系统提取或请求补充来源、项目背景、相关文件。
4. 系统推荐 Agent 和 Skill。
5. 用户确认并保存任务。

### 3.2 任务启动 Agent

1. 用户打开任务详情。
2. 系统展示 Context Pack：来源、项目背景、文件、步骤、Agent、Skill。
3. 用户可以编辑 Context Pack。
4. 用户选择 Codex、Claude 或 Cursor。
5. 系统打开对应应用，并将可复制/可注入的 Prompt 传入。
6. 系统创建 Agent Run，状态为 `launched`。

### 3.3 结果沉淀

1. 用户返回工作台，补充或粘贴 Agent 结果。
2. 系统记录运行状态、日志摘要、修改文件、测试结果和产物链接。
3. AI 可生成结果摘要和下一步建议。
4. 用户确认任务为完成、继续、阻塞或需要重试。

### 3.4 今日行动

1. 系统根据项目活动、未完成任务、最近来源和历史结果生成推荐。
2. 用户查看推荐理由。
3. 用户确认后加入今日列表，也可以拒绝或调整优先级。
4. 首页只突出已确认的行动，避免 AI 推荐直接变成噪声。

## 4. 功能需求

### P0：MVP 必须有

#### F-01 今日行动首页

- 首页默认显示“今日行动”，而不是来源目录或知识条目。
- 每张任务卡显示：标题、项目、来源、状态、推荐 Agent、推荐 Skill、最近结果。
- 支持按项目筛选、按状态筛选、手动调整排序。
- 支持快速创建任务。

#### F-02 任务草稿生成

- 输入一段自然语言想法。
- AI 生成可编辑的标题、目标、项目候选、执行步骤和推荐 Agent/Skill。
- 生成结果必须可拒绝或修改，不能静默写入外部系统。
- 生成失败时保留原始输入。

#### F-03 多项目关联

- 一个任务可以关联多个项目。
- 项目提供描述、目录、相关来源和历史任务上下文。
- 用户可手动添加或移除关联项目。

#### F-04 Context Pack

- 默认包含：来源、项目背景、执行步骤、推荐 Agent、推荐 Skill。
- 可追加相关文件路径和历史执行结果。
- 启动前显示完整预览。
- 用户可以编辑后再启动。

#### F-05 Agent 启动适配器

- 首版同时提供 Codex、Claude、Cursor 三种适配器入口。
- 最低能力：打开对应应用并生成可注入的完整 Prompt。
- 适配器必须返回启动状态和失败原因。
- 自动发送属于后续能力，不能阻塞 MVP。

#### F-06 Agent Run 记录

- 记录 Agent、开始时间、结束时间、任务快照、状态和结果。
- 支持保存完整结果文本或结果摘要。
- 支持记录修改文件、测试/验收结果和产物路径。
- 支持状态：`draft`、`launched`、`running`、`succeeded`、`failed`、`blocked`、`cancelled`。
- 失败时只记录并提示用户，不自动重试或切换 Agent。

#### F-07 Skill 推荐与草稿

- 根据任务和来源推荐已有 Skill。
- 当内容可能适合沉淀为 Skill 时，生成 Skill 草稿。
- Skill 草稿必须经用户审核后才能保存或写入 Skill 目录。

#### F-08 来源捕获

- MVP 先支持工作台内快速输入。
- 保留 URL、文本和文件路径等来源类型。
- 浏览器扩展、右键菜单、剪贴板自动捕获作为后续入口，但数据模型必须预留。

### P1：MVP 后第一阶段

- 浏览器扩展与右键捕获。
- GitHub Issue 导入与外部链接同步。
- 从 IDE 侧创建任务。
- 自动提取 Agent 修改文件和测试结果。
- 任务模板与可复用 Context Pack。
- 批量处理来源和任务。

### P2：暂不规划

- 无人值守自动执行。
- 自动切换 Agent 重试。
- 完整的团队协作权限系统。
- 替代 Notion、Obsidian 或 GitHub Issues 的全部能力。

## 5. 信息架构

主导航建议：

1. **今日行动**：首页，聚焦当前要推进的任务。
2. **任务**：全部任务、状态、项目和来源。
3. **项目**：项目上下文和相关任务。
4. **Agent 运行**：执行队列、日志、结果和产物。
5. **来源**：网页、文件、对话和外部事项。
6. **Skill**：已有 Skill、推荐 Skill、待审核草稿。
7. **设置**：Agent 路径、启动命令、文件来源和偏好。

当前原型中的“工作区 / 文件收集 / 收件箱”映射：

| 当前模块 | MVP 中的角色 |
|---|---|
| 工作区 | 项目上下文 |
| 文件收集 | 来源同步 |
| 收件箱 | 未处理来源队列 |
| Skill 库 | Agent 执行策略库 |
| Review | Agent Run 结果与历史 |

## 6. 非功能需求

- 本地优先：任务、上下文和执行记录默认保存在本地 SQLite。
- 原始文件不被移动、覆盖或删除。
- 启动 Agent 前必须显示将要传递的内容。
- 外部命令执行必须显示命令、工作目录和状态。
- 任务和运行记录可导出为 Markdown/JSON。
- AI 生成失败时，用户仍能手动创建和编辑任务。
- 所有关键操作提供可见的成功/失败状态。

## 7. 验收场景

### 场景 A：记录想法并启动 Agent

给定：“把最近看到的性能优化思路应用到 Jupiter 社区项目。”

系统应能：

1. 生成任务草稿。
2. 推荐 Jupiter 项目。
3. 给出执行步骤。
4. 推荐 Codex/Claude/Cursor 和相关 Skill。
5. 展示可编辑 Context Pack。
6. 打开指定 Agent 并填入 Prompt。
7. 保存 Agent 返回结果和修改文件。

### 场景 B：执行失败

给定 Agent 返回失败。

系统应能：

1. 将 Run 标记为 `failed`。
2. 保存错误摘要和已有日志。
3. 保留任务和 Context Pack。
4. 让用户选择修正上下文、重新启动或关闭任务。

## 8. 风险与待验证项

- Codex、Claude、Cursor 在 Windows 上的启动与 Prompt 注入方式不同，需要先做适配器技术验证。
- “记录完整日志、修改文件、测试结果”可能需要 Agent CLI/API 或人工回填，不能假设所有应用都开放接口。
- AI 推荐今日行动容易制造噪声，必须保留用户确认层。
- 跨项目任务可能造成上下文过载，需要限制默认注入内容并支持折叠。
- 外部任务作为事实来源时，需要设计同步冲突规则。
