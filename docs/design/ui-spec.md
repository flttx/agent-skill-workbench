# 工作台 UI 规范

> 版本：0.1 · 更新日期：2026-08-06  
> 适用范围：工作台所有页面、弹窗、表单、任务卡片和 Agent 执行界面。

## 1. 设计目标

工作台是“个人 AI 工作操作系统”，界面要帮助用户快速完成：捕获信息、理解上下文、选择下一步行动、执行并回看结果。

因此 UI 优先级固定为：

1. 行动清晰：用户一眼知道当前页面的主要动作。
2. 上下文完整：来源、项目、步骤、Agent、Skill 和结果之间的关系可追溯。
3. 状态可信：草稿、待推进、执行中、阻塞、完成有明确且一致的视觉表达。
4. 克制而稳定：深色、紫色只用于建立层级和强调，不用装饰效果掩盖信息结构。

## 2. 当前截图审计结论

Quick Capture 当前版本存在四个 P0/P1 问题：

- 输入框和文本域显示为浏览器默认白色控件，与深色主题冲突；这是控件没有使用共享样式的实现问题。
- 标签、输入内容、辅助说明的层级不够稳定，字段高度和内边距没有统一约束。
- 表单底部的保存动作、提示文案和字段区域缺少明确的操作层级，用户不容易判断“保存后会发生什么”。
- 双列布局没有根据字段权重做区分；标题、目标、步骤、来源应先保证可读性，再追求压缩空间。

本规范的硬性底线：项目中不得出现未接入样式的浏览器默认文本输入框、文本域、复选框或选择器。

## 3. 视觉基础

### 3.1 色彩与质感

颜色与材质必须使用 `src/design-system.css` 中的变量，不在页面 CSS 中重新发明近似颜色。

| 用途 | Token | 说明 |
|---|---|---|
| 页面背景 | `--bg` | 全局深渊黑曜石底色（`#0a090e`），配合动态呼吸星云与科技点阵 |
| 面板背景 | `--surface` / `--glass-bg` | 卡片、输入框、列表项的半透黑曜石玻璃底色（`#13111a`） |
| 抬升背景 | `--surface-raised` | 弹窗、激活项、二级容器（`#1c1826`），带深邃悬浮阴影 |
| 边框 | `--line` | 默认边界 |
| 强边框 / 高光 | `--line-strong` / `--border-specular` | 容器 1px 镜面顶光反射与选中边界 |
| 主文字 | `--text` | 标题、正文和已确认内容（`#f5f2fa`） |
| 次文字 | `--muted` | 标签、说明和辅助信息（`#a7a0b5`） |
| 弱文字 | `--subtle` | 时间、占位符、非关键提示（`#736b80`） |
| 核心流光 / 强调 | `--accent` / `--accent-strong` | 星云紫主要操作与激活流光（`#a855f7` / `#c084fc`） |
| 科技辅助流光 | `--cyan` / `--cyan-strong` | 赛博青辅助数据、运行中状态与高光流动（`#06b6d4` / `#22d3ee`） |
| 辉光光晕 | `--accent-glow` / `--cyan-glow` | 按钮、选中卡片与状态点的外发光漫射（Bloom） |
| 成功/警告/危险 | `--success` / `--warning` / `--danger` | 极光绿 / 琥珀金 / 珊瑚红状态表达 |

对比度要求：正文和主要操作必须清晰可读；`--subtle` 只用于非关键元信息，不得承载错误、状态或唯一操作提示。

### 3.2 字体和字号

- 正文使用 `Manrope, "Microsoft YaHei", sans-serif`。
- 技术标识、状态码、Agent/Skill 名称可使用 `DM Mono, monospace`。
- 页面标题：29–38px；区块标题：16–23px；卡片标题：13–16px；正文：12–13px；辅助信息：10–11px。
- 标题使用紧凑字距；正文保持 `1.5–1.7` 行高。
- 英文小标题（`eyebrow`, `card-kicker`）使用 `DM Mono`，配合微荧光文字阴影建立科技 HUD 质感。

### 3.3 间距、圆角、阴影与动效

- 间距以 4px 为基数，优先使用 8、12、14、16、20、24、28px。
- 控件默认高度为 `--control-h`（40px）；紧凑按钮最低 32px。
- 小控件圆角使用 `--radius-sm`，普通卡片使用 `--radius` 或 `--radius-lg`。
- 容器采用黑曜石玻璃拟态（`backdrop-filter: blur(24px) saturate(180%)`）搭配 1px 镜面顶光反射（`--border-specular`）。
- 交互动效包含卡片鼠标聚光灯（`Spotlight`）、霓虹流光边框、SVG 拓扑图能量流行动画（`energyFlow`）。
- 动效使用 `--ease`；必须尊重 `prefers-reduced-motion` 并优雅降级。
- 控件默认高度为 `--control-h`（40px）；紧凑按钮最低 32px。
- 小控件圆角使用 `--radius-sm`，普通卡片使用 `--radius` 或 `--radius-lg`。
- 普通面板使用低强度多层阴影和 1px 镜面顶光；弹窗、抽屉再提升阴影与模糊层级，避免所有容器都使用同一强度。
- 矩形按钮、筛选按钮和切换按钮统一使用 `--border-specular` 作为顶部边框；选中态使用 `--border-specular-hover`，不得用独立的 inset 白色高光替代。
- 动效使用 `--ease`；必须尊重 `prefers-reduced-motion`。

### 3.4 沉浸式氛围与交互光效

- `ambient-nebula-container` 固定在应用内容层之后，承载主题化的静态弥散光斑与低透明 HUD 网格，不阻挡点击和滚动。
- 卡片和面板的 Spotlight 使用 `requestAnimationFrame` 节流；鼠标坐标按当前容器计算为局部变量，只在悬停或键盘聚焦时显示，避免全屏泛光。
- `.border-beam` 只用于当前导航、选中 Skill 等明确激活态；普通卡片不持续播放边框动画。
- 拓扑连线使用 `graph-flow-pulse` / `energyFlow` 的 dash 流动，节点 hover 和 current 状态增加紫青双层漫射。
- 背景星云和网格不播放位移动画；`prefers-reduced-motion: reduce` 下继续关闭边框流光、连线脉冲和 Spotlight 过渡，信息层级、焦点环和状态文字保持不变。

## 4. 页面结构

每个页面都应有稳定的三段结构：

1. 页面头部：页面名称、当前上下文和一个主要动作。
2. 内容区域：按信息层级组织面板，不把所有内容塞入一个巨型卡片。
3. 状态反馈：空状态、加载、成功、错误和阻塞状态都要有可解释的反馈。

首页默认以“今日行动”为入口。页面不得仅展示统计数字而没有下一步动作；每个核心指标至少要能跳转到对应任务或列表。

布局约束：

- 内容最大宽度：`1080–1250px`，由页面复杂度决定。
- 常规面板间距：14–16px；同一表单字段间距：12–14px。
- 双列表单只用于两个字段具有相近阅读权重的情况；长文本字段默认单列或跨列。
- 小于 760px 时所有双列表单、指标和操作区改为单列。
- 页面滚动只发生在内容区，侧栏和顶栏保持稳定。

## 5. 表单规范

### 5.1 字段结构

每个字段必须是“标签 → 控件 → 可选说明/错误”的顺序。标签要说明用户需要填什么，不用 placeholder 代替标签。

```tsx
<label>
  任务标题
  <input className="field-control" ... />
</label>
```

所有普通 `input`、`textarea` 必须使用 `.field-control`。特殊复合控件（搜索框、Radix Select）可以使用自己的容器规范，但不能裸用浏览器默认样式。

### 5.2 输入控件

- 背景使用 `--surface`，文字使用 `--text`，边框使用 `--line`。
- 单行输入高度 40px，左右内边距 11px；文本域左右内边距 11px、上下内边距 10px。
- placeholder 使用 `--subtle`，不能承担真实内容或关键说明。
- 聚焦时使用 `--accent-strong` 边框和可见 focus ring，不改变布局尺寸。
- 文本域默认最小高度 100px；任务步骤、来源等长文本字段可使用 120px 以上。
- 允许用户调整文本域高度，但不能出现水平滚动条。
- 禁止使用白色浏览器默认背景、默认蓝色 outline 或未定义的 checkbox 样式。

### 5.3 选择和复选

- 选择器使用统一的 `SelectControl`，触发器高度、边框、打开态和选中态保持一致。
- 复选框必须放在带边框的 `.check-option` 中，点击区域至少 30px 高。
- 多选项的选中态同时改变边框、背景和文字，不只依赖一个小勾。
- 表单只有一个最主要的提交动作；取消、关闭和次要动作使用 secondary/ghost 样式。

### 5.4 表单操作区

- 操作区与字段区之间至少 16px，并用上边框或明确间距分隔。
- 主按钮文案必须描述结果，如“保存任务”“启动 Agent”“记录结果”，避免只写“确定”。
- 保存中必须禁用按钮并显示“保存中”；成功后给出可见反馈或回到任务上下文。
- 辅助文案不能贴着主按钮造成竞争；如果是重要行为说明，应放到按钮上方或字段附近。

## 6. 任务和执行状态

Task 是工作台核心对象，任务卡片必须优先展示：标题、状态、关联项目、目标和下一步动作。

状态颜色和语义固定：

- 草稿：中性紫灰，仅表示尚未确认。
- 待推进：紫色，表示可以开始。
- 执行中：琥珀色，表示正在占用用户注意力。
- 被阻塞：红色，必须同时显示阻塞原因或下一步解阻动作。
- 已完成：绿色，必须保留结果入口或历史记录。

Agent、Skill、来源属于上下文元信息，使用紧凑标签展示，不得抢过任务标题和状态的视觉优先级。

## 7. 交互、可访问性和反馈

- 所有图标按钮必须有 `aria-label`；图标本身使用 `aria-hidden="true"`。
- 所有交互控件必须支持键盘访问，并有可见 `:focus-visible` 状态。
- 不用颜色作为唯一状态表达；状态同时提供文字、图标或结构提示。
- 错误要出现在相关字段附近，并说明如何修复；不把原始异常直接展示给用户。
- 弹窗打开时聚焦首个可操作元素，关闭后返回触发按钮。
- 空状态必须解释为什么为空，并提供一个明确的开始动作。

## 8. 禁止事项

- 禁止页面级别直接写新的近似色值代替已有 token。
- 禁止裸用 `input`、`textarea`、`select`、checkbox。
- 禁止一个页面同时出现多套按钮高度、选择器形态或表单标签写法。
- 禁止为了“看起来丰富”给普通面板添加大量发光、渐变、漂浮动画。
- 禁止把来源、项目、Agent、Skill 和执行结果压缩成无法阅读的一行。
- 禁止在没有成功、失败和加载状态的情况下接入异步操作。

## 9. 页面验收清单

开发完成后，逐项检查：

- [ ] 页面有清晰标题、上下文和唯一主要动作。
- [ ] 所有普通输入控件都使用共享字段样式，没有白色默认控件。
- [ ] 字段标签、placeholder、错误和辅助说明层级清楚。
- [ ] 主要按钮、次要按钮、关闭按钮的视觉优先级正确。
- [ ] 768px 以下布局不会横向溢出，表单会变成单列。
- [ ] 键盘 Tab 顺序合理，focus 状态可见。
- [ ] 空、加载、保存中、成功、错误、阻塞状态均有反馈。
- [ ] 任务上下文和执行结果可回看，不只保存一个标题。
- [ ] `pnpm check` 与 `pnpm build` 通过。

## 10. 本次落地范围

本轮先处理截图中最影响观感和复用性的基础问题：

1. 建立本规范作为后续页面的 UI 约束。
2. 增加共享 `.field-control` 和 `.field-checkbox` 样式。
3. 将 Quick Capture 的标题、目标、步骤、来源、Skill 和项目复选框接入共享控件。
4. 将规范和开发进度文档互相链接，后续新增页面按验收清单自检。
## 11. 全面改版的工作台外壳约束

全面改版阶段不以当前侧边栏菜单作为信息架构。主导航优先保留“工作台、项目上下文、任务执行、设置”四个稳定空间；捕获是全局动作，来源、Skill 和复盘分别作为捕获状态、资源层和执行时间线出现。首页必须同时呈现下一步任务、待整理来源和执行状态，不能退化为单一任务列表。

新页面优先使用上下文抽屉、局部面板和任务工作区承载细节，避免继续增加平级菜单。所有新捕获入口必须明确保存后的去向、项目关联状态和是否会生成任务。
> 滚动容器补充：页面级滚动区域与抽屉、详情面板重叠时，界面只显示一条纵向滚动条；内容仍须支持滚轮、触控板和键盘滚动。

## 12. Skill 专用工作台约束

- 可见主导航只保留“本机 Skill、调用历史、设置”。其他模块可以保留实现，但不得与 Skill 管理争夺首屏入口。
- Skill 首屏只保留一个主要动作层级：优化本机 Skill 为主动作，更新外部 Skill 为次主动作，打开目录为辅助动作。
- 分类使用简单标签或筛选条；不得在默认视图展示关系拓扑、复杂连线或多层统计卡片。
- 完整正文、变体关系、使用笔记和跨 Agent 复制必须通过明确的折叠/详情入口渐进展示。
- 调起 Cursor/Codex 前必须展示 Skill 路径、工作目录和完整 Prompt 预览；默认不自动发送。
- 调用历史默认使用时间倒序列表，支持按 Skill 搜索和按 Agent 筛选；更新命令输出不混入调用历史。

## 13. Skill 与设置页布局契约

- Skill 页面桌面端使用“左侧 Skill 列表 + 右侧详情”的双栏结构；`skills-library-grid` 必须显式使用 CSS Grid，不允许退化为纵向堆叠。
- 功能筛选条必须使用胶囊按钮和激活态，禁止出现浏览器默认灰色按钮背景或无间距的连续文字。
- Skill 卡片描述左对齐、字号 11–12px、最多显示 3 行；卡片标题、Agent 标签和版本数的优先级高于长描述。
- 设置页的 Skill 更新命令按“Agent 名称 → 命令输入 → 启用 → 保存”排列；复选框必须是暗色主题控件，不能使用默认灰色原生外观。
- 页面切换时内容滚动区域回到顶部，标题和首个面板不得被前一次页面的滚动位置遮挡。
- 顶部搜索、同步和状态反馈使用明确的两行操作区：第一行放置主要操作，第二行放置状态文本；不得依赖 inline 流布局产生换行。
- Skill 详情标题、动作按钮和来源元数据分成三个层级；元数据使用两列字段网格，长描述和路径位于字段网格之后。
- Skill 详情不创建独立纵向滚动条，长内容由页面级滚动区域承载，避免列表页出现双滚动容器。

## 14. 全局星空主题契约

- 工作台提供四套深色主题：创生之柱、黑洞引力、恒星编织者、宇宙山脉；首次启动默认使用创生之柱。
- 主题同时控制页面背景、玻璃面板、文字层级、按钮、焦点环、边框、SVG 图表和交互光效；页面不得直接写主题专属颜色。
- 星空背景固定在应用底层，必须经过深色遮罩；背景图不能承载业务信息，也不能阻挡点击和滚动。
- 背景氛围层保持静态，不使用雾光呼吸、光球漂移或网格移动来干扰内容阅读；`prefers-reduced-motion` 下同样保持主题与信息层级不变。
- 侧边栏使用主题专属的半透明玻璃层（`--sidebar-bg`），应保留背景图的可见性，同时保证导航文字和焦点态清晰。
- 主题选择同时出现在设置页和顶栏快捷入口。选择后即时应用，并通过本地存储在下次启动恢复。
- 顶栏主题快捷浮层使用独立的 fixed 层挂载，必须位于页面内容层之上，不得被 Skill 详情面板或页面滚动容器遮挡。
- 主题卡片必须展示背景缩略图、主题名称、色板、当前选中态和键盘焦点；不能只依赖颜色表达选中状态。
- 成功、警告、危险等状态色保持稳定语义，同时显示文字或图标，不得只依赖颜色。
- 背景动画、网格、Spotlight 和边框流光在 `prefers-reduced-motion: reduce` 下关闭，主题 Token 和可读性保持不变。
