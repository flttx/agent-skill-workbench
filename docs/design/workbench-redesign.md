# 个人 AI 工作台全面改版方案

## 设计结论

工作台不是“任务、收件箱、Skill、复盘”等页面的集合，而是一个把分散信息转成下一步行动的个人操作系统。

当前侧边栏菜单只是早期原型实现，不作为目标信息架构。后续开发先完成工作台外壳和核心工作流，再把现有任务、来源、Skill 和 Agent Run 能力迁移进去。

## 目标用户流程

```text
看到想法 / 网页 / AI 对话 / GitHub 事项 / 本地文件
→ 一键捕获
→ 工作台识别来源和意图
→ 关联项目与上下文
→ 生成或关联任务
→ 推荐 Agent / Skill
→ 预览上下文并执行
→ 回填结果、改动、验证和下一步
→ 回到工作台继续推进
```

## 目标信息架构

### 1. 工作台首页：行动驾驶舱

首页不是任务列表，而是当前状态和下一步的总控面：

- 顶部提供全局捕获入口和搜索/命令入口。
- 中心区域显示“现在最应该推进什么”，包含进行中任务、阻塞任务和待确认结果。
- 侧边或抽屉显示待整理来源，不强迫用户先进入收件箱页面。
- 项目脉冲显示近期变化、相关来源、Agent 结果和风险。
- 运行中的 Agent 和待保存结果直接出现在首页。

### 2. 统一捕获层：所有入口先进入同一条处理链

统一捕获支持：

- 想法和待办。
- 网页 URL 和文章摘录。
- AI 对话片段。
- GitHub Issue / PR 链接。
- 本地文件或目录。

捕获后先形成 `Source Draft`，再由用户确认是否归档、关联项目、生成任务或沉淀 Skill。捕获入口可以是弹窗、快捷键、剪贴板或浏览器入口，不对应一个必须长期停留的菜单页。

### 3. 项目上下文：围绕项目组织事实

项目上下文不是简单的工作区目录列表，而是一个可供任务调用的上下文空间，包含：

- 项目目标、背景和本地目录。
- 相关来源、文件和知识条目。
- 关联任务和最近执行结果。
- 可用 Agent、Skill 和项目约束。
- 当前健康状态和需要处理的问题。

项目切换应影响上下文推荐和执行默认值，但不能隐藏跨项目任务。

### 4. 任务工作区：从任务详情变为执行控制台

任务详情需要围绕“下一步怎么做”组织，而不是单纯表单：

- 任务目标和完成定义。
- 来源证据和项目背景。
- 可编辑的 Context Pack。
- 执行步骤、推荐 Agent 和 Skill。
- Agent Run 时间线。
- 最终改动、验证、问题和下一步决策。

任务可以从来源生成，也可以将多个来源合并到同一个任务；保存 Agent 结果不能自动完成任务。

### 5. 资源层：来源、文件和 Skill 作为上下文资源

来源、文件和 Skill 不作为与任务平级的主流程页面，而作为可搜索、可关联、可复用的资源层：

- 来源保留原始链接/路径、摘要和处理状态。
- 文件展示相对项目路径、内容摘要和可用状态。
- Skill 展示适用场景、关联 Agent、推荐理由和审核状态。
- 资源详情都提供“关联任务”“关联项目”“加入上下文”的动作。

### 6. 执行层：结果回到任务和项目

Agent Run 是任务的执行时间线，不单独成为用户必须理解的“复盘模块”：

- 启动前显示工作区、Prompt、Agent 和 Skill。
- 执行中显示状态和降级原因。
- 执行后显示结果草稿、最终改动和验证信息。
- 无法匹配的记录进入待确认区，但不污染任务归属。

## 目标导航形态

目标导航采用“少量主空间 + 全局捕获 + 上下文抽屉”，不复刻当前菜单：

1. **工作台**：行动驾驶舱和全局状态。
2. **项目上下文**：项目、来源、文件、任务和资源关系。
3. **任务执行**：任务工作区和 Agent Run 时间线。
4. **资源搜索**：来源、文件、Skill、结果的统一搜索结果页或抽屉。
5. **设置**：系统配置和适配器状态。

“捕获”是全局动作；“收件箱”是来源处理状态；“Skill 库”和“复盘”是资源/执行视图，不应占据与工作台同等的主导航权重。

## 现有实现迁移关系

| 当前原型 | 全面改版后的归属 |
|---|---|
| 今日行动 | 工作台首页的行动驾驶舱 |
| 工作区列表 | 项目上下文切换器 |
| 工作区概览/知识/来源/活动 | 项目上下文内部的分区和抽屉 |
| 收件箱 | 统一捕获后的待整理状态 |
| Skill 库 | 资源搜索和任务上下文中的 Skill 面板 |
| 复盘 | 任务执行时间线和首页待确认结果 |
| 任务详情 | 任务工作区/执行控制台 |
| 设置 | 系统设置，不参与日常工作流 |

## 改版开发顺序

### 阶段 A：信息架构和交互原型

- [ ] 确认工作台首页、统一捕获、项目上下文、任务工作区四个核心场景。
- [ ] 画出来源 → 项目 → 任务 → Agent Run → 结果的状态流转。
- [ ] 确认主导航、抽屉、弹窗和命令入口，不继续扩展当前侧边栏。
- [ ] 按 UI 规范产出可评审原型。

### 阶段 B：工作台外壳重构

- [ ] 重构 App Shell、首页布局和全局捕获入口。
- [ ] 将当前任务卡片、待处理来源、Agent 状态整合到首页。
- [ ] 建立全局搜索和命令入口的对象类型分组。

### 阶段 C：统一捕获与来源处理

- [ ] 建立 Source Draft 统一数据结构。
- [ ] 接入文本、URL、GitHub、本地文件和 AI 对话片段捕获。
- [ ] 支持来源整理、归档、忽略、关联项目和生成任务。

### 阶段 D：项目上下文与任务工作区

- [ ] 重构项目上下文视图，支持文件、来源、任务和资源的关系展示。
- [ ] 将任务详情改造成 Context Pack + 执行时间线。
- [ ] 把 Agent Run、最终改动和结果决策嵌入任务工作区。

### 阶段 E：资源和 Agent 能力迁移

- [ ] 将 Skill 推荐、Skill 草稿审核放入任务上下文和资源层。
- [ ] 保留 Codex、Claude、Cursor 适配器，但从任务工作区统一启动。
- [ ] 完成结果回填、最终基线差异和待确认记录。

### 阶段 F：全链路验收

- [ ] 想法、网页、GitHub、AI 对话、本地文件均能进入统一捕获层。
- [ ] 来源可进入项目、生成任务并执行。
- [ ] Agent 结果能回到任务和首页。
- [ ] 用户无需在多个旧菜单之间手动搬运上下文。

## 暂停的方向

在阶段 A/B 完成前，暂停以下工作：

- 继续给当前侧边栏增加独立菜单。
- 单独扩展“收件箱页”“Skill 页”“复盘页”的复杂功能。
- 只围绕 Agent 手工验收，而不验证完整工作台流程。
- 把工作台做成通用文件管理器或知识库替代品。
### 本机 Skill 视图保留决策（2026-08-07）

资源层不是隐藏入口。工作台保留独立的“本机 Skill”视图，用于按名称、Agent、适用场景和本地路径查找 Skill，查看完整用法、变体和可复制命令；任务上下文中的 Skill 推荐继续作为快捷入口，但不替代资源视图。

### Skill 专用工作台收敛（2026-08-21）

基于实际使用频率，本轮将可见工作台进一步收敛为“本机 Skill / 调用历史 / 设置”。Skill 分类复用现有自动功能组，不新增手工分类维护；调用历史复用本地 Agent 历史解析结果；外部更新继续执行已配置的更新命令；本机优化通过用户确认后调起 Cursor 或 Codex，并保持不自动发送 Prompt。

功能拓扑、关系图、使用笔记和复制到其他 Agent 不删除数据或后端能力，但从 Skill 首屏移入“查看完整用法、版本和关系”的渐进式详情区域。
