# 产品上下文

## 产品名称（暂定）

个人 AI 工作操作系统 / Personal AI Work OS

## 一句话定位

连接浏览器、文件系统、IDE、Codex、Claude、Cursor 的个人工作操作系统：把分散的信息转成可执行任务，推荐合适的 Agent 与 Skill，打开工具执行，并保存全过程和结果。

## 已确认的用户方向

- 主要场景：同时推进多个个人项目。
- 使用方式：工作台长期打开，第一屏关注今日行动。
- 核心痛点：工具太多，信息和行动分散。
- 核心对象：任务；项目、来源、Skill、Agent 执行记录都围绕任务服务。
- 产品角色：跨工具控制层，而不是替代 GitHub、Todo 应用、IDE 或 Agent。
- 自动化边界：AI 可以理解、总结、生成建议和草稿；用户确认后才启动执行。
- MVP 首要闭环：想法 → 任务 → 推荐 Agent/Skill → 打开 Agent → 保存结果。

## 核心工作流

```text
快速捕获想法
  → AI 生成任务草稿
  → 关联一个或多个项目
  → 推荐 Agent / Skill
  → 预览并编辑上下文包
  → 打开指定 Agent 并自动注入 Prompt
  → 记录日志、文件、测试和结果
  → 回到今日任务，决定下一步
```

## 设计原则

1. 行动优先：首页回答“今天该推进什么”，而不是“我收集了什么”。
2. 上下文完整：任务必须能携带来源、项目背景、文件、步骤、Agent 和 Skill。
3. 人在回路：AI 推荐和生成草稿，用户确认后才创建外部任务或启动 Agent。
4. 外部工具优先：外部系统保留事实来源，工作台维护关联、上下文、编排状态和执行结果。
5. 可追溯：任何执行都能回看输入、工具、过程、产物和验证结果。
6. 渐进集成：先支持“打开应用并注入 Prompt”，再扩展自动发送和深度 API 集成。

## UI 规范

具体的视觉 token、布局、表单、状态、可访问性和验收要求见 [工作台 UI 规范](./ui-spec.md)。该文件是后续页面开发的 UI 约束，不以单页临时样式替代。

## 暂不解决的问题

- 不做完整的 Notion / Obsidian 替代品。
- 不做新的通用文件管理器。
- 不在 MVP 中实现复杂的自动任务调度和无人值守执行。
- 不要求工作台成为所有外部任务系统的唯一真实来源。
## 当前改版决策

工作台后续按全面改版推进，不以当前侧边栏菜单作为产品信息架构。目标是以工作台首页、统一捕获、项目上下文和任务执行控制台串联想法、网页、AI 对话、GitHub、本地文件、Agent 和 Skill。现有“收件箱、Skill 库、复盘”等页面视为过渡实现，逐步迁移为捕获状态、资源层和任务执行时间线。详细方案见 [`workbench-redesign.md`](./workbench-redesign.md)。

## Skill 工作台收敛决策（2026-08-21）

当前首要使用场景确认是本机 Skill 管理，因此可见工作台收敛为三个空间：本机 Skill、Skill 调用历史、设置。项目、任务、收件箱和 Agent Run 数据及后端能力保留，但不再作为本轮主导航。

Skill 首屏只突出查找/分类、查看详情、更新外部 Skill 和启动 Cursor/Codex 优化本机 Skill。功能拓扑、关系图、使用笔记和跨 Agent 复制降为详情中的渐进式内容。Skill 调用历史只读取可识别的本机 Agent Skill 使用记录，不与更新命令日志混合。

## 全局主题决策（2026-08-25）

工作台采用四套深色星空主题，默认主题为“创生之柱·秘境苍金”。主题切换影响全局视觉 Token 与背景氛围，不改变任务、Skill、Agent 和调用历史等业务数据。背景图固定在内容层之后并使用遮罩，状态颜色保持稳定语义；用户可从设置页或顶栏快捷入口切换，选择通过本地存储恢复。

## 今日首页 MVP P0 设计方向（2026-09-22）

- 首版只交付“今日首页”，唯一最高强调动作是“更新项目进度”。
- 默认项目按置顶顺序选择，没有置顶时按最近活跃项目兜底；不可用项目不自动替换。
- 进度草稿采用确定性证据聚合，Codex 与 Git 必须同时可用；不可用时首页只读。
- 草稿版本保存到工作台，不写回项目文档；用户确认字段受到后续同步保护。
- 今日首页围绕一个当前项目组织完整工作流：状态检查、进度草稿、保存版本、历史查看和项目上下文跳转必须在同一页可达；辅助快捷入口不得绕过 Codex/Git 可用性门槛。
- 周报、周看板和 `codex-cli` 生成暂不进入首版 P0。
- 今日首页 P0 补齐（2026-10-08）：项目可配置本地进度文档来源；保存时重新确认数据源可用；证据冲突由用户取舍，保留草稿和历史版本；项目搜索只切换上下文，不自动生成或启动 Agent。

## 已确认的界面优化方向（2026-10-08）

- 用户选择“保留星空、降低内容区干扰”。首轮范围为今日页与应用外壳，不扩大为其他页面整体重设计。
- 四主题及背景图片保留；内容区使用稳定深色面板和柔和遮罩，降低装饰网格、光晕与导航光效。颜色和按钮仍跟随主题。
- 信息与主动作优先：单一页面标题、项目名旁切换、当前阶段/完成/下一步、数据源状态；生成后由保存承担最高强调。
- 全局同步集中到顶栏“同步全部”；“刷新项目状态”只更新今日项目状态；Git查看显示已读取状态并就地反馈。
- 窄屏使用紧凑横排导航，先满足项目、状态与主动作首屏可达，再呈现辅助信息。
- 首次使用（2026-10-08）：用户可直接从今日空态添加本地项目；添加成功自动选中该项目，生成与保存仍遵守数据源门槛。工作台记录关联和版本，不初始化Git或修改项目文件。
