# 阶段 6：真实项目场景验收与收敛计划

## 目标

用真实项目验证从“想法”到“任务”再到“Agent 执行结果”的完整闭环，确认 MVP 能减少工具切换、上下文重复复制和结果遗漏。

本阶段先验收和记录，不以新增功能为默认目标。只有验收暴露出明确问题时，才进入最小范围修复。

## 执行顺序

### 1. 基础链路验收

- [ ] 从模糊想法创建任务。
- [ ] 关联一个或多个项目/工作区。
- [ ] 检查来源、背景、执行步骤、推荐 Agent 和 Skill。
- [ ] 预览任务上下文并确认 Prompt。
- [ ] 启动 Agent，确认 Prompt 不自动发送。

### 2. Agent 适配验收

每类 Agent 至少执行一次：

| Agent | 验收重点 |
|---|---|
| Codex | 启动命令、工作区、Prompt 注入、历史匹配 |
| Claude | 启动命令、工作区、Prompt 注入、历史匹配 |
| Cursor | 同目录复用、不同目录新窗口、Ctrl+N 新会话、Ctrl+V 填充、终端降级 |

每次启动都要确认 `agent_runs` 中存在任务 ID、Agent、工作区、Prompt 快照、启动状态和错误信息。

### 3. 结果回填验收

- [ ] 刷新历史后能生成结果草稿。
- [ ] 摘要、改动文件、验证结果和未解决问题支持编辑。
- [ ] 保存结果后运行记录变为已保存。
- [ ] 保存结果不会自动把任务改为已完成。
- [ ] 无法匹配的会话进入待确认，不强行归属。
- [ ] 用户可以将待确认记录关联到已有任务或忽略。

### 4. 最终改动文件验收

以 Agent 启动时的工作区基线和刷新时的最终状态为准，逐项验证：

- [ ] 新增文件显示绿色 `+`。
- [ ] 修改文件显示黄色 `~`。
- [ ] 删除文件显示红色 `−`。
- [ ] 修改后恢复原状不显示。
- [ ] 新建后删除不显示。
- [ ] 启动前已有修改不归因到当前任务。
- [ ] Agent 期间提交 Git 后，仍能识别相对启动基线的最终变化。
- [ ] `.gitignore`、依赖、构建和缓存目录不进入结果。
- [ ] 中间触碰但最终恢复的文件出现在单独区域。
- [ ] 基线或扫描失败时显示警告，不伪造删除记录。

### 5. 连续使用验收

- [ ] 第二天从“今日行动”继续任务。
- [ ] 任务详情能查看历史运行记录和上次结果。
- [ ] 多任务并行时显示工作区并发警告。
- [ ] 应用重启后仍能读取运行记录。
- [ ] 失败或终端降级后，用户能恢复 Prompt 和上下文。

## 通过标准

### 必须通过

- 三类 Agent 均能产生运行记录。
- Prompt、工作区和任务关联准确。
- 结果保存和任务完成状态保持独立。
- 最终改动文件不把中间恢复内容误报为结果。
- 失败、待确认和降级状态都有明确反馈。

### 可接受限制

- Agent 历史格式变化导致的解析失败，但必须保留来源路径和错误原因。
- Cursor UI 自动化失败后进入终端降级，但不能误操作其他窗口。
- Vite chunk 体积提示和既有 Rust unused/dead_code 警告。

### 不通过条件

- 运行记录缺失任务 ID 或 Prompt 快照。
- 不同工作区的历史被错误归属。
- 保存结果自动修改任务状态。
- 启动前已有文件变化被错误计入当前任务。
- UI 自动化失败时向错误窗口发送快捷键或 Prompt。

## 记录模板

每个验收场景在 `docs/development-progress.md` 记录：

```text

实际：

运行记录 ID：

```

## 修复优先级

1. P0：错误归属、数据丢失、误操作其他 Agent 窗口。
2. P1：核心链路无法完成、结果无法保存、改动文件误报。
3. P2：提示不清晰、布局问题、历史记录展示问题。
4. P3：视觉细节、性能优化和非核心体验改进。

## 阶段退出条件

- 必须通过项全部完成。
- P0/P1 问题已修复并重新验证。
- 工程验证通过：`cargo fmt --check`、`cargo test`、`cargo check`、`pnpm check`、`pnpm build`。
- 进度文档包含完整验收记录、遗留问题和 MVP 阶段结论。
